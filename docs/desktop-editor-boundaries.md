# 桌面头像与提示词预览的异步边界

2026-10-03。源码修复与真实 Electron 证据；正式发行包另行验证。

头像处理的成功结果已经按角色与选择次数过滤，但旧图片的解码错误原先直接写入当前编辑器。实际窗口先开始读取无效 JPEG，再选择有效 PNG，延迟拒绝旧解码后仍显示错误。现在成功与失败使用同一角色/选择次数检查；裁剪读取的迟到错误也不会覆盖其他角色或新图片。当前无效图片仍显示可纠正的错误，旧头像与先前有效草稿保持可用。

提示词预览原先只依赖故事 ID 与输入草稿；在同一个故事编辑消息、切换分支或保存候选后，已展开的预览不会刷新。现在依赖实际 `activeBranchId/updatedAt`，取消上一请求并清除旧内容，生成结束后恢复刷新。迟到响应不能覆盖最新预览。

`apps/desktop/scripts/verify-renderer-editor-boundaries.mjs` 在独立 profile 运行真实 React/SQLite。失败报告 `portrait-before-20261003-r1` 和 `preview-before-20261003-r1` 分别实测旧头像错误覆盖和分支预览未刷新，保留原报告。修后 `renderer-editor-boundaries-editor-after-20261003-r6.json` 的七阶段通过，checkedAt 与完整诊断保存在报告中，SHA-256 为 `0f15570776aec309a7428f25d7a729cff41a7bbc817af6c035f2c130fa09198a`：

- 延迟无效旧图片不会覆盖新 PNG；实际 HTTP 503 保留旧头像和待保存文件，原文件重试保存后的全部像素一致。
- 当前无效 WebP 被拒绝，有效重选恢复；旧角色的迟到失败不会写入其他故事的角色编辑器，回到原角色仍有有效草稿。
- 实际编辑分支与同分支宿主保存自动刷新已展开预览，输入草稿保持不变。
- 实际关闭、新服务端口和 profile 重启后，从故事列表打开已保存故事，消息内容保持一致。

PNG 头像接口可包含重新写入的角色卡文本块，因此检查保存后的全部图像像素，不把原上传 PNG 容器字节相等当成要求。r2 是这一过严自编断言失败；r3/r4 是自编 harness 假设 sessionStorage 能跨新端口自动恢复选中故事；r5 在同一次 React 批次往返导航而未触发列表读取。这些失败报告保留，后续没有删掉产品断言。

renderer 的迟到预览单元回归与类型检查通过。这些证据不代表完整 C01、U05、真人 G05 或旧正式 EXE 已完成。
